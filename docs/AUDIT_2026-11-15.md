## Existing patterns worth preserving

- Raw verification/reset tokens are hashed before database persistence.
- Verification tokens are limited to 24 hours; password-reset tokens to
  30 minutes; token redemption is one-time.
- Authorization reads user identity from validated JWTs.
- Email session notifications are queued with distinct `Queued`,
  `Processing`, `Sent`, `Failed`, and `Previewed` states.
- Local `*.db` files and common secret files are Git-ignored.

## Remaining issues / incomplete integration to investigate

1. **External Brevo delivery is unverified.** Confirm SMTP login vs API key,
   transactional account activation, authenticated sender/domain, deliverability
   and recipient status in Brevo Transactional logs. This cannot be proven
   from source control or by checking the length of a key.
2. **Student booking UI is incomplete.** The student dashboard currently
   lists sessions but does not expose a mentor-discovery/booking form even
   though corresponding backend APIs exist.
3. **Other frontend/API gaps.** Review whether student-visible notification,
   review, reschedule and completed-session record features are wired to
   real API data. Backend endpoints are present; no corresponding dedicated
   student UI was found in the tracked Angular route tree.
4. **Auth security:** add rate limiting to register/login, forgot-password
   and resend routes; review account mail retry policies and leakage risks.
5. **Production settings:** frontend link base URL is currently localhost;
   production requires HTTPS, origin configuration and deploy configuration.
6. **Coverage:** no verified browser end-to-end test of Student→Mentor
   booking/approval/reschedule/cancel/review, no real-inbox test, and no
   local build evidence from the user's open VS Code workspace.

## Recommended continuation order

1. Merge only after CI has passed and local changes are safely reconciled.
